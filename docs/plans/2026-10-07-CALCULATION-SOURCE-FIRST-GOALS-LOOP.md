# 计算书原文优先与人工原文输入 — Goals Loop Plan

日期：2026-10-07
状态：方案已整理，尚未开始本计划的代码修改、部署或 E2E。
仓库：Membership 与 AIPlanner 符号链接对应的 AICMDEngine。

## 1. 总目标及边界

将计算书处理统一为“取得基础原文 → 保存来源版本 → 结构化整理 → 人工审核 → 发布与重建”。原文既可以来自图片识别，也可以来自用户提供的 Markdown／HTML＋LaTeX。最终交付必须包括两个仓库必要的代码、契约及回归测试、目标服务部署，以及部署后真实模型和浏览器端到端测试；源码测试通过不等于目标完成。

本计划更新 2026-10-06-GENERIC-CALCULATION-PIPELINE-GOALS-LOOP.md 的计算书要求：每条公式生成的语义说明可选；整份计算书或当前片段的总说明仍然必需。旧计划中的“每条公式语义必需”不得继续作为本范围的发布门槛。独立公式及普通数据表的既有契约不受此例外影响。

明确排除：普通数据表处理重写、跨页合并存储、计算执行与有限元、RAG 算法重写、全库历史数据修复、全局模型切换。现有单页、批量、JSON 编辑以及人工审核发布机制必须保持可用。

本轮用户请求是编写计划，不是立即执行。执行会话须取得用户开始执行的指令；部署与 E2E 是本计划的必做目标，不能以离线检查代替。提交、推送及真实业务内容发布须核对各自授权，不将写计划视为操作授权。不得凭本文自动向其他 agent 发送消息。

## 2. 不可破坏的规则

1. 原文与计算书结构分别保存；生成解释与原文事实区分。
2. 用户明确选择的原文必须成为本次输入，旧 Markdown 不得覆盖它；不允许静默回退到图片识别。
3. 原文版本、对象身份、页码、租户、运行 ID 和结构化结果建立可追溯关联；来源文本哈希与原 PDF 哈希分别记录。
4. 已发布内容和已有有效草稿不能因新的识别、整理或发布失败被清空。
5. 原文每个条目有输出对应或明确的未完成记录，不能以删除条目使校验通过。
6. 原文条件、附注、符号解释必须保留；生成的逐项语义为空不构成内容缺失。
7. 总说明只描述实际提供内容；缺页不猜补，续页片段可独立审核发布。
8. 原文变化后，旧结果和旧人工确认不能自动视为新版本已审核。旧版本仍可查看。
9. 租户及对象权限由服务端校验，过期版本与并发更新必须显式冲突，禁止覆盖他人编辑。
10. 不能以特定页号、表号、标准名称或公式写识别特例。

## 3. 统一链路与界面

### 3.1 两种输入

- 图片入口：沿用自动上传分类、人工指定类型及重新抽取入口，确定为计算书后取得可读原文。
- 人工入口：当前计算书对象下新增“使用人工提供的原文”，支持粘贴 Markdown／HTML＋LaTeX、源码编辑及安全渲染预览。
- 初版一份原文对应一个计算书对象。一页含多个计算书时分别处理；不把整个页面文本无提示地灌入一个对象。批量为每个对象使用其独立来源。

操作含义：

| 操作 | 行为 |
|---|---|
| 保存原文 | 保存版本和来源，不发起模型调用，不直接改写结构化或已发布内容 |
| 根据此原文整理计算书 | 使用明确保存的来源版本，只进行文本整理，产生草稿 |
| 整理已有原文 | 使用当前选定的有效来源版本，不隐式选择旧识别结果 |
| 重新抽取 | 实际发送当前对象图片生成新原文，再走共用整理链路 |
| 保存计算书草稿 | 保存结构化编辑，不伪装成已重新识别 |
| 发布与重建 | 对当前审核结果执行既有发布生命周期及索引重建 |

输入框有未保存修改时必须明确提示保存或取消；不可直接用后台旧文本启动整理。界面清楚显示当前来源类型、版本、整理状态及结果对应的版本。

### 3.2 阶段 A：图片转原文

模型专注忠实识别标题、分节、公式、条件、附注及归属，不要求复刻表格网格和左右栏版面。允许 Markdown／HTML 表达必要的关系，数学内容保持完整 LaTeX。先持久化原文，再运行阶段 B。空响应、截断、无效格式分别诊断，截断原文不能标为完整。

人工原文直接进入阶段 B。用户粘贴的内容是选定来源，不代表系统已证明其相对原图完全准确；界面提供对照能力，不擅自改正数学含义。

### 3.3 阶段 B：原文整理

扩展既有 MCP 预处理和计算书解析器，不创建第二套平行转换服务。

- 使用结构感知方式识别标题、分节、表格单元、HTML 换行及完整数学边界。不能以简单换行、逗号或竖线拆断公式。
- 保留共同适用范围及每条公式附属条件；分成 sections/items 数组，分配来源 ID、版本及范围。
- 模型负责条目类型、关系和整体说明，逐项补充解释可为空。来源中的 LaTeX 为依据，模型不能无证据替换公式。
- 同名符号、相同公式在不同条件下可重复出现，不能按符号或文本全局去重。
- 输出逐项校验并回填；辅助字段失败只标记该字段，不能丢弃整条原文或公式。模型漏项必须保留可编辑原文条目并标记待补齐，不伪装完成。
- 长内容按完整条目分批；根据实际批次数安排有界执行或可恢复后续任务，不随意提高无限请求预算。记录完成与未完成批次，只重试必要部分。
- 单页、批量、自动上传、人工指定类型共用此核心逻辑。批量隔离各对象的身份、输入及失败状态。

### 3.4 审核与片段

当前页完整性和整份计算书齐全程度分别记录。有 Cont’d／Continue／续且缺前页时，保留片段标记和标题，缺页只作为上下文信息。整页内容审核完成可发布。不得因此虚构前页关系或强制等待。

保存和人工确认后从当前草稿重新计算诊断；历史提取错误单独展示。必须区分可人工确认的内容疑问与不能绕过的空内容、无效结构、对象/版本不匹配问题。整个计算书无总说明时提示补齐；逐项说明为空不能触发该提示。

## 4. Goals Loop 执行规则

每个目标按“取得基线证据 → 写失败用例 → 最小修改 → CodeGraph sync → 定向验证 → 检查差异 → 记录结果”循环。失败必须定位到具体阶段；不能仅靠重试直到偶然通过。未通过的目标不得标记完成。

每个循环记录：目标、基线、变化文件、测试及实际结果、遗留问题、下轮动作。真实请求记录最少必要的对象/版本/运行身份、模型标识、阶段、请求计数与耗时，不记录密钥或正文到普通日志。真实文档、响应、登录态放受限临时证据目录，不进入仓库。

执行前核对仓库真实路径、分支、HEAD、dirty hunks、AGENTS.md、相关 docs/specs 及当前运行版本。执行 codegraph status/query/context；每批源码修改后 sync，未经确认不全量重建索引。保护已有无关文件及用户编辑。

## 5. 分目标与退出条件

### G0 — 基线与契约冻结

- 复核 Membership 的原文选择、任务创建、恢复、保存和发布路径，以及 MCP 的转录、分节、结构化和预算实现。
- 重点复核 ReviewObjectRecoveryService 中旧 Markdown 覆盖 existingContent 的行为；不能仅凭 UI 参数认定已使用新原文。
- 定义最小来源版本与结果绑定契约，优先复用既有草稿版本和任务生命周期；描述现有持久化数据的兼容读取，不强制历史批量迁移。
- 明确当前配置模型，不变更全局配置。固定测试文档、对象清单及发布隔离方式。

退出：变更层次、输入优先级、身份与版本规则、测试矩阵有明确记录；基线无歧义。

### G1 — 人工原文入口完整纵向切片

- 实现输入、预览、保存和按指定版本整理；Membership 明确传递来源，MCP 复用文本整理入口。
- 后端验证身份、非空内容、支持格式和现有容量限制；拒绝过期版本。
- 保留旧原文及已发布内容；失败不丢用户输入。
- HTML 预览遵循现有消毒规则，不执行脚本或事件处理器。

退出：粘贴 → 保存 → 刷新 → 整理 → 保存草稿可完成；保存原文零模型调用，文本整理零图片调用；所用文本哈希与用户保存版本一致，旧 Markdown 无法覆盖。

### G2 — 通用源条目保留与结构化

- 完善数学边界、HTML/Markdown 结构、共同条件和条目 ID。
- 保留全部源条目；可选字段失败不删除公式；分批覆盖完整且可恢复。
- 调整每条语义可选、整体说明必需的 MCP/消费方契约。

退出：不同合成版式、超过单批容量、重复符号、附带第二个数学条件的公式均不漏项；模型缺项/截断/局部字段失败有可见恢复结果；不能假通过。

### G3 — 两种入口与单页/批量一致

- 图片转录先保存，再复用 G2；人工原文跳过阶段 A。
- 自动上传识别出的计算书与人工指定计算书走共同实现。
- 单页和批量使用同一对象处理逻辑；一个对象失败不覆盖其他对象成果。

退出：相同来源走单页及批量得到等价内容、归属与条件（忽略运行 ID 和时间）；图片路径有真实图片请求，文本路径无图片请求；普通数据表回归不变。

### G4 — 审核、片段与发布一致性

- 调整当前诊断、历史诊断、确认状态及原文版本变更行为。
- 总说明缺失需补齐；条目说明空值允许；孤立续页不阻止本页发布。
- 发布及重建失败保留有效原文、草稿和原已发布版本。

退出：保存刷新、人工确认、发布后读回内容一致；来源更新不继承旧确认；无前页片段可发布；空结构/无总说明不能错误发布；并发和跨租户负例通过。

### G5 — 离线回归及交付检查

- MCP：既有 calculation_processing/calculation_sheet/input 等相关测试，新增通用合成用例。
- Membership：原文保存/输入优先级/版本/任务/发布服务定向测试及受影响模块编译。
- UI：输入预览、未保存状态、错误、刷新、重复操作、旧结果提示及生产构建。
- 更新本范围的契约文档；新 Python 文件如确有必要，检查两个 Dockerfile 的显式 COPY。
- 检查最终差异、工作区、git diff --check。提交只在执行会话明确授权后进行。

退出：相关测试与构建通过，无无关变更；每项检查的实际命令和结果记录齐全。

### G6 — 目标环境部署与回滚准备

- 重新确认真实 checkout、版本/工作区树摘要、Compose 文件、镜像、服务及环境；不照抄旧记录。
- 预计影响 PDF2MDEnhanced MCP、Membership API、DocIntel UI；以实际改动核定服务清单，只部署受影响单元，不重启无关 Router/数据库。
- 保存旧镜像与部署配置；记录可执行的定向回滚命令。
- 构建目标镜像并定向部署，验证启动日志、健康检查、实际运行代码/产物与待验收版本一致。
- 部署失败恢复旧服务；数据格式须允许安全回滚读取，不能靠回滚镜像掩盖不兼容数据变更。

退出：所有受影响服务运行正确版本且健康，原功能冒烟通过；回滚材料齐全。此时只代表部署通过，不代表 E2E 通过。

### G7 — 已部署系统真实 E2E

执行浏览器 → Membership API → MCP → 已配置模型 → 草稿持久化 → 浏览器读回。核对真实提供方请求与阶段信息，不以 mock 或接口单测冒充 E2E。

用例：

1. **人工原文 p18**：使用用户本次提供的 Table 4.16.4 Markdown。检查 17 条公式、共同法兰适用范围及 e/d/X_h 各分支条件；保存刷新一致；不调用图片识别；明确证明未使用旧 Markdown。
2. **图片入口 p16**：密集公式、多批次页面。与原图独立建立条目清单，不只使用历史计数作为真值；全部批次及条目可核对，未完成不得隐藏。
3. **未处理过的新对象**：选择非 p13_t2、非仅用来调试的页面，覆盖不同版式或混合注释。先确认无人工草稿/发布成果；先固定验收清单，再运行。
4. **孤立续页**：缺少前页的测试片段，确认可独立审核保存发布，整体说明不虚构完整计算书。
5. **批量**：两个独立对象与单页处理对照；混入一个可控失败，其他对象成功且身份/原文不串用。
6. **审核发布全程**：在隔离测试文档/版本中确认、发布、重建、刷新、关闭重开并读取已发布内容及索引关联，条目和来源不丢失。业务文档默认只生成草稿；不得为测试直接覆盖用户已发布成果。
7. **失败恢复**：受控环境模拟截断、批次失败、版本冲突、发布失败；生产环境不人为破坏服务。验证保留已有成果、可继续处理、诊断刷新。

新文档外发前核对明确授权范围，不能把此前 p16/p18 授权扩展到未知页面。若隔离环境或权限不具备，标记具体阻塞并完成其余测试，不能跳过后声称 E2E 完成。不得再次使用用户明确排除的 p13_t2。

退出：以上正常路径和异常路径有逐项结果及受限证据；公式准确性与原文核对，不能以渲染正常替代。对未处理新页失败须回到通用实现修正，再重跑受影响矩阵。

### G8 — 最终验收报告

报告改动范围、契约变化、测试矩阵、部署版本、真实模型、调用次数/耗时、已发布与仅草稿对象、数据保留验证、回滚方法及剩余限制。明确提交/推送/镜像构建/部署/数据发布各自状态。

仅当 G0–G7 退出条件均满足才标记总目标完成。有阻塞或未执行的真实测试必须保持未完成状态。
