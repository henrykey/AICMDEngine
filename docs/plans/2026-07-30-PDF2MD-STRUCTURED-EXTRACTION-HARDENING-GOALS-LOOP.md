# PDF2MD Structured Extraction Hardening Goals Loop

日期：2026-07-30
状态：Executing（Goals 1–3 已取得首轮证据与最小修复）
责任边界：`AICMDEngine/mcp/servers/PDF2MDEnhanced` 负责页面与结构化元素提取；Membership / DocIntel 负责接收、持久化、索引与 Review 展示。
动机：当前扫描标准 PDF 中可见页眉残留、条款层级被铺平、表格未能进入数据库、公式偶有丢失；这会直接破坏 Table Lookup、检索和两份独立文档专业比较。

- 已实现：Membership 从 MCP Markdown 表回退解析列和行；零行表不再视为完整，沿既有未完成表清单报告。

- 待用本地 fixture 验证：真实 PDF 页的自动 GLM→VLM 路由、复杂表格合并单元格、公式/图形端到端对象，以及 Review/Table Lookup 消费。

## 1. 最终目标

让扫描 PDF 经 PDF2MD Enhanced 提取后，稳定产出可被 DocIntel 使用的、可审计的页面文本与结构化元素：

```text
PDF 原件
  -> PDF2MD Enhanced: 页面布局/OCR/清洗/结构化元素
  -> Membership ingestion: page_text + tables + formulas + figures
  -> Mongo / search index / Review
  -> Table Lookup / 检索 / 专业比较 / 来源预览
```

验收不是“页面有文字”，而是每个已识别对象在 MCP 输出、Membership 持久化、Review 和下游消费中均可追溯。

## 2. 范围与非范围

### 包含

1. 重复页眉、页脚和可识别水印的检测与清理。
2. 页面文本中的条款结构恢复，包括编号独占行与下一行标题、编号中的 OCR 空格。
3. 表格提取、规范化和端到端入库诊断与修复。
4. 公式的原始/LaTex 表示与语义描述。
5. 图形的来源定位与语义描述。
6. PDF2MD MCP 与 Membership ingestion 的稳定元素契约、错误状态和回归样本。
7. 以受控重建验证 GB/T 16749-2018 等真实扫描文档，不直接覆盖已验证的生产数据。

### 不包含

1. 不改双文档专业比较的业务语义或报告规则。
2. 不把 Table Lookup 逻辑搬入 PDF2MD MCP。
3. 不以手工逐页编辑 Markdown 作为修复方案。
4. 不更换 OCR/VLM 供应商，除非基线证据表明现有引擎无法输出所需对象。
5. 不在本计划中改造 Membership UI 的视觉样式。

## 3. 目标数据契约

### 3.1 页面文本

- 保留阅读顺序、页码与来源定位。
- 删除跨页重复页眉/页脚；水印不得污染正文、标题或表格单元格。
- 标题以稳定层级输出；例如 `3.7` 单独一行、下一行为“加强环”时，输出为一个结构化标题。
- 不伪造无法从页面支持的标题、文本或数字。

### 3.2 表格

每个表格必须包含：`element_id`、页码、边界/位置、标题或可用名称、表头、行列、单元格文本、来源置信度和原始证据引用。

Membership 成功接收后，必须能在数据库中查到对应表格记录，并由 Table Lookup 以该记录而不是页面散文替代。

### 3.3 公式与图形

- 公式：保存可用的 LaTex 或原始公式表示、页码/位置及受证据约束的语义描述。
- 图形：保存页码/位置、图题（若有）及语义描述；描述不是原图或来源证据的替代物。
- 无法可靠提取时必须返回明确状态（例如 `UNREADABLE` / `LOW_CONFIDENCE`），不能静默丢弃。

### 3.4 状态与可观测性

每页和每个元素需区分：`EXTRACTED`、`PERSISTED`、`INDEXED`、`LOW_CONFIDENCE`、`FAILED`、`SKIPPED`。日志只记录最小标识、页码、对象类别、数量和稳定错误码；不得记录全文、模型提示词、响应或凭证。

### 3.5 Advanced Process：重新规范化页面内容

为每份文档提供受控的 Advanced Process 操作：`renormalize page content`。

- 它属于 **Stage 1**：输入为已经保存的原始页面文本，输出为清洗、分段并带 Markdown 标记的规范页面内容。
- 它不重新下载源 PDF、不重新 OCR、不改变原始 PDF，也不调用模型改写专业正文。
- 文档页面的入口名称为 **Renormalize and Rebuild**：一次检查并处理该文档的全部页面，不需要用户逐页选择或确认。
- 每页先作确定性质量检测。已有可信 Markdown / 无需清洗的页不写入、不改变；仅不合格页执行规范化。
- 原始页面文本和本次规则/版本保留为内部来源记录，不新增用户可见的草稿确认步骤。
- 完成后只使实际改变页面的 Stage 2 派生物失效：表格、公式、图形、页面索引和向量索引按需要重建；不得把“只重建索引”误认为已完成结构提取。
- 任一页面规范化或重建失败时，保留该页既有内容并记录稳定失败状态；不得以空文本、空元素或部分覆盖替换原有正确数据。

## 4. 固定回归样本

在实施前冻结最少三类、可授权使用的 PDF fixture：

1. `GBT16749-2018` 的典型术语/通用要求页：含 `3.7`、`3.8`、`3.9`、`4.1` 等跨行标题和页眉。
2. 含复杂边框、合并单元格和数字列的扫描表格页。
3. 含公式与图形的扫描页。

每个 fixture 记录 PDF 哈希、页面号、期望标题/表格/公式/图形清单。测试数据不得含无授权的商业标准全文；可用最小裁剪页或脱敏 fixture。

## 5. Goals Loop

每个 Goal 必须遵循：

```text
建立可复现失败样本或测试
  -> 定位 MCP 输出与 Membership 持久化的边界证据
  -> 实现该 Goal 的最小改动
  -> 运行聚焦回归
  -> 检查真实 MCP payload、数据库记录和 Review 结果
  -> 未满足 Exit criteria 则记录证据并回到本 Goal
```

### Goal 1：建立端到端损失基线

目标：明确每一种缺失发生在 PDF2MD 输出、Membership 接收、数据库写入还是索引阶段；禁止凭 UI 现象归因。

行动：

1. 对三个 fixture 运行当前 PDF2MD MCP，保存去敏的 page/element 清单快照。
2. 对每页记录实际提取路径：PDF 文本层、OCR、布局/Markdown 生成、fallback 或人工修订；解释为什么同一文档的不同页路径不同。
3. 对照 Raw 页面文本、Rendered Markdown、Membership 接口请求、Mongo 持久化记录、Review 页面和 Table Lookup 可见性。
4. 为每个异常标注首次丢失边界：`MCP_OUTPUT`、`MARKDOWN_FORMATTING`、`INGESTION`、`PERSISTENCE`、`INDEXING` 或 `REVIEW`。
5. 记录页眉、条款标题、表格、公式、图形的数量和可追溯 ID。

验证：

- 能回答“表格不存在”究竟是 MCP 没输出，还是 Membership 没入库。
- `GBT16749` 第 7 页的原始 page_text、结构标题和 Review 显示互相对照。
- Raw 文本中的换行与 Rendered Markdown 的段落/标题差异有明确归因；不得把 Markdown 软换行折叠误判为 OCR 失败。

Exit criteria：

- 每类问题都有可复现样本和首次丢失边界。
- 不在没有基线证据前修改 OCR、数据库或比较逻辑。

### Goal 2：页面清洗与条款结构恢复

目标：输出无重复页眉/页脚污染、可用于章节级消费的页面文本。

行动：

1. 基于跨页重复性、位置和文本形态识别页眉/页脚；只删除满足证据规则的内容。
2. 对直接取得文本层但未带 Markdown 的页面，执行确定性的 Markdown 格式化；不得只把原始换行直接交给 Markdown renderer。
3. 对 OCR 编号作保守规范化，例如 `3. 10`、`4 .1`，保留原始文本引用。
4. 合并“编号独占行 + 相邻标题行”，形成稳定章节标题和正文边界。
5. 对无法判定的页面保留原文并标为低置信度，不进行猜测性重写。

验证：

- GB/T fixture 的 `3.7` 至 `3.14`、`4.1`、`4.2` 被正确分段。
- 第 7 页在 Rendered 模式中显示为标题、段落和换行，而非单一折叠段落；Raw 文本仍可完整追溯。
- 页眉不出现在正文、标题、表格标题或嵌入索引文本中。
- 页内普通数字、公式编号和表格行号不被误删或误判为章节标题。

Exit criteria：

- 每个 fixture 的预期条款标题均可被稳定识别。
- 对照原始页面，无新增/丢失的正文段落。

### Goal 3：表格对象的输出、持久化和 Table Lookup 闭环

目标：已识别表格能够以规范结构进入数据库并被 Table Lookup 使用。

行动：

1. 定义 MCP 表格 payload 的必填字段、空表格规则与稳定错误码。
2. 增加 MCP 对复杂表格、合并单元格和数字列的回归断言。
3. 追踪 Membership ingestion 到 `doc_tables` 或等价持久化模型的字段映射与事务结果。
4. 用真实已入库表格验证 Table Lookup 返回标题、页码、列名和相关行。
5. 表格解析失败时持久化失败状态与来源定位，不能以空对象表示成功。

验证：

- MCP payload、数据库记录、Review 清单和 Table Lookup 数量一致。
- 一个表格对象可从 Table Lookup 回链到原 PDF 页。

Exit criteria：

- 三类 fixture 表格均有可查询持久化记录或明确失败状态。
- 不再需要通过手工补表来让基本 Table Lookup 生效。

### Goal 4：公式与图形的可追溯语义对象

目标：公式和图形不再静默丢失，且下游可基于对象而非猜测性正文使用它们。

行动：

1. 为公式输出原始/LaTex 表示、页码、位置、语义描述和置信度。
2. 为图形输出图题、页码、位置、语义描述和原图引用。
3. 为无法识别的对象输出明确状态并保留页面级来源。
4. 验证 Membership 映射、持久化与 Review 可见性。

验证：

- 公式 fixture 的关键 LaTex/原始表示与语义描述均存在。
- 图形 fixture 能显示语义描述并回链到来源页。
- 失败对象不被伪装成已提取成功。

Exit criteria：

- 公式、图形各至少一个端到端真实对象通过。
- 对象计数在 MCP、数据库与 Review 之间可解释。

### Goal 5：受控重建、旧文档兼容与消费者验证

目标：验证修复可安全应用到既有文档，而不是只对新上传文档有效。

行动：

1. 在文档 Advanced Process 中实现并验证 `Renormalize and Rebuild`：一次检查该文档全部页面并直接应用必要的 Stage 1 改动。
2. 验证合格页字节级保持不变，不合格页才生成规范 Markdown；不产生用户确认用的 draft。
3. 人工核对页面文本、章节目录、表格、公式和图形。
4. 只对实际改变页面执行相应 Stage 2 与索引重建；页面失败保留旧内容并继续处理其它页面。
5. 验证检索、Table Lookup、来源预览和双文档比较消费的是新结构。
6. 为旧格式 page_text 保留下游兼容读取，不在本 Goal 修改双文档比较的业务规则。

验证：

- 章节级比较不再把正常条款页降级为 `Page N`。
- `Renormalize and Rebuild` 对第 7 页不调用 OCR；对这份文档的其它已合格页不产生内容变化。
- 一页发生异常不会覆盖该页旧内容，也不会阻止其它页面完成。
- 表格查询命中结构化表格，而不是手工补录或正文猜测。
- 回滚到旧版本不会破坏当前文档可访问性。

Exit criteria：

- 至少一份真实文档从重建到下游消费完整通过。
- 更新范围、数据变更和回滚方式有记录。

### Goal 6：发布门槛与运行交接

目标：将提取质量变成持续门槛，而非一次性人工修复。

行动：

1. 将固定 fixture 回归纳入 PDF2MD Enhanced 聚焦测试。
2. 增加 MCP contract 测试，以及 Membership ingestion/persistence 集成测试。
3. 对部署前输出对象数量、失败状态和关键字段做预检。
4. 更新运行指南：如何诊断对象在何边界丢失、如何走 Review 草稿、何时允许重建。

验收：

- 所有 fixture 的页面清洗、章节、表格、公式、图形断言通过。
- 对象从 MCP 到数据库再到下游消费均可追溯。
- 不记录敏感文档正文或模型内容。
- 不出现“UI 看起来有表、数据库没有表”或“空对象被标为成功”而没有稳定错误状态的情况。

## 6. 实施顺序和提交边界

1. 先完成 Goal 1；未定位首次丢失边界，不实施功能修复。
2. 页面文本/标题（Goal 2）、表格（Goal 3）、公式图形（Goal 4）分别独立提交。
3. Membership ingestion 的必要修复必须在对应 Goal 的证据表明其为丢失边界后，才在 Membership 仓库另行实现和测试。
4. 真实文档重建、部署和提交均须在各 Goal Exit criteria 满足后获得单独授权。
