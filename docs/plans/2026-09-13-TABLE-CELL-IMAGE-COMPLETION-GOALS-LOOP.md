## 需要补齐的内容

### 1. 恢复触发和执行时序

当前 recovery_blocks 只选 layout_content 阶段 FAILED 的对象；表格文字成功后，语义阶段才发现图片缺坐标，现有恢复已经结束。补齐语义结果之后的图片完整性检查：有图但区域缺失、部分图片缺失、区域无效时进入同一恢复生命周期。无图表格不触发；已具备有效图片区域的单元格不重复识别。未知状态不得当作确认无图。

### 2. 恢复输出的实际能力

不能只重新调用当前 _recover_layout_objects：其 table 分支调用 extract_table_html，仅获得 HTML，没有单元格图片几何。需要在已有对象恢复入口内补齐表格图片几何目标，复用现有 VLM 客户端、对象绑定、裁剪与调用计数，输出原契约 source_cells[].image_regions。不得用纯 HTML 恢复成功作为图片恢复成功条件，也不得覆盖已正确识别的文字和表格结构。

### 3. 裁剪坐标与源单元格关系

复用可信表格 bbox 裁剪。模型读取的是裁剪图时，坐标明确属于裁剪图；利用实际 crop_info 将单元格和子图坐标转换回原页，不能直接标成 normalized_page。验证页码、表格身份、行列、rowspan/colspan、包含关系和重复身份。覆盖缩放、padding、旋转策略、边缘和非整数坐标；缺少可信变换时拒绝生成资产。图片标识在同一次恢复及重复应用时保持稳定。

### 4. 预算和终止条件

沿用现有对象数、模型调用/重试及图像资产预算。初次与后续恢复共享计数，不因第二阶段执行而重置额度，不增加无界循环。实施前核对各入口的实际计数归属；需要额外预算或改变调用策略时先明确提出，不隐式放宽。耗尽、截断、无效JSON、模型不可用均保留可解释未完成状态。正常纯文字表格不增加调用。

### 5. 合并和完整性状态

合并仅补图片证据，不替换OCR文字、HTML、正确单元格或已有图片。检查重复/冲突候选、多图单元格、部分成功和重复恢复。恢复成功时仅清除已解决的图片错误，保留其他问题；缺坐标、裁剪失败或预算失败不能清空后变成成功。完整性状态贯穿原始返回、归一化与页面输出，文字语义和图片完整性分开判断。

### 6. 统一资产与入口覆盖

继续使用 _attach_cell_image_figures -> _attach_figure_assets；不增加存储后端或整表图替代逻辑。逐一核对整页layout路径、非layout路径、单页tables/structured、structure_target与紧凑响应。object_crop/title-only保持已有语义范围，不伪造原页资产。记录每个入口是否具有可信源几何与恢复预算；不支持时显式未完成。Membership端只读核对适配、cell_object_refs、资产落库及展示，若确需改动则先列出具体缺口与最小范围。

## 必测矩阵

- 整页OCR表格成功但没有图片区域：后置恢复被调用，图片最终可解码，父表/单元格正确。
- 原始响应已经有有效图片区域：无需额外识别；重复处理不重复添加图片。
- 纯图片、图文混合、同一单元格多图、多个单元格及合并单元格；至少一种与第12页不同的布局。
- 纯文字/数值表格不误生成图片，不增加图片恢复调用；公式及已有正确图形不受影响。
- 裁剪图坐标准确投影到原页，用有颜色/位置特征的图像验证实际裁剪内容，而非只检查非空PNG。
- 缺失/错误/越界坐标、错误父表、重复身份、部分恢复、模型异常或截断、调用预算耗尽、图片预算失败。
- 恢复成功后旧缺图错误清除；无关错误仍在；失败状态不被表格语义成功覆盖。
- 真实文档验收检查图片内容与单元格关系，不仅检查任务COMPLETED或资产数大于0。
