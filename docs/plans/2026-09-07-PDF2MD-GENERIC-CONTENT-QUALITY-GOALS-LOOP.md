## 1. 总目标与不可变边界

目标是通用文档内容提取：正确保留和解析复杂表、公式、图像，生成符合文档语言的语义描述，并把有充分证据的表格转换为可查询数据。ASME、GB/T151 仅是困难回归样本，不得引入按标准名称、文件名、页码或特定数值分支的修补规则。

增强现有实现，不替换已经有效的抽取与渲染路径。保留原始 HTML/Markdown、LaTeX、对象身份和来源。查询派生数据不得覆盖展示原文。原文错误与派生结构错误必须区分。

MCP 负责内容解析、语义补全、表格查询投影、对象关系和质量证据。Membership 负责授权、目标选择、任务/重试/分批续跑、当前版本验证、持久化、页面回写、资产保存、索引及 UI。本计划不得修改 Membership 或业务数据库。

执行该计划不包含提交、推送、镜像构建、容器启动/重启、部署或真实模型调用；这些动作需要用户另行授权。允许本地源代码修改、离线测试和必要契约文档更新。不得将 provider stub 或人工标注作为真实模型验收。

## 4. Goals Loop 方法

每个 G 按以下循环执行：记录现状与不变量 → 建立失败用例 → 最小修改 → 验证用例由失败转通过 → 相关回归 → 自审 diff → 更新执行报告与下一步。

每轮报告必须包含：目标、证据、改动文件、失败前结果、修复后结果、未解决项、下一轮动作。不得因调用返回 200、status complete 或测试数量增加便宣布内容质量达标。

遇到合同变更影响现有消费者时，先明确兼容影响和 Membership 必须配合的事项；不得静默改变 complete/partial 的含义。完成独立可做工作，再报告真正阻塞点。

## G1：贯穿语言约束与可靠的语义返回

目标：文档语言作为生成描述的约束，英语文档不能接收实质中文说明为成功，反之亦然；原文中的牌号、公式、符号和引用标题不强制翻译。

工作：

- 追踪初次抽取、单页、对象恢复、对象增强中现有语言传递，修复实际遗漏，复用统一的语言解析/校验能力，不再创建相互分化的检测路径。
- 对生成的 semantic_desc 等自然语言字段实施结果校验，覆盖“英文标题＋中文正文”。对短名称、符号等证据不足的内容避免错误判定。
- 语言不符返回明确原因和 unresolved 字段，不接受为已修复。明确整次无效与部分字段有效的响应规则，沿用单对象、仅请求字段、身份严格匹配的契约。
- 不增加 Membership 内模型重试；MCP 若已有调用预算则必须遵守，语义接口现有单次调用策略不得被暗中变成多次。
- 保留 request_id、模型逻辑调用次数、无敏感内容的原因码。澄清 complete 与 requested fields 完整恢复的区别。

验收：en/zh 正反例、混合语言漏检、合法技术符号、空响应、身份不符、字段越界、模型失败均有回归；原始 HTML/LaTeX 不变；各入口语言传递有合同测试。

## G2：已有 HTML 到可查询数据

目标：在现有 query_enhancement 中将可靠网格解析与语义解释连接起来，而非重新 OCR 或让模型抄写表值。

工作：

- 评估并迁入现有 probe 脚本经验证的 pandas＋lxml 处理方法，使用增强服务既有依赖管理；不得复制成第二个独立增强服务。记录现有解析器可复用部分及确需修改的证据。
- 保持行顺序、前导零、空格/空值语义、原始字符串，避免 pandas 自动数值转换或自动表头吞行。处理 rowspan/colspan、thead/tbody/tfoot 和全 td 表头。
- 用 HTML 来源单元格和合并原点建立位置映射，不能仅以“相同文本出现过”证明来源；覆盖重复文本和空单元格。
- 先确定性投影；歧义只在显式 semantic_review/model_required 且有预算时请求模型。模型提出表头层级、分区、单位、行键、脚注和条件的来源引用，不改写数据值。
- 保持全部来源文本的覆盖或显式 unresolved，防止漏列、漏注释却标 complete。
- 精确标签查询与范围/条件执行分开：`150~475` 可保留为标签，但无端点证据不能推断闭区间；条件未满足不能返回无条件结果。
- 保留 v1 complete/unavailable 与 candidate_sections 的安全语义。部分表可查询属于跨服务合同扩展：本轮先保留可验证候选和明确范围，不把诊断候选直接发布为可查询。需要新合同则在交接中列出，不能单侧启用。
- 更新依赖声明、两种镜像的打包静态/隔离导入验证及契约；不实际构建镜像。

验收：

- 对可读取的 47 张 HTML 重跑，报告解析成功率、坐标/合并来源正确性、自动语义投影通过数及每张阻塞原因。
- 保留已有 5 个手工查询基准，并增加自动确定表头后的结果核对；明确二者证据等级。
- 合成测试覆盖多级表头、体内分组、全 td 表头、重复值、前导零、脚注、单位、缺少续表上下文、恶意/越界模型引用和超限输入。
- 不以 47/47 网格成功代替全部语义查询成功；未通过表必须有具体原因，不能普遍归并为 ambiguous_header。

## G3：恢复表格整体及表内公式关系

目标：初次提取与定向恢复正确保留父表，表内公式不替代整个表格。

工作：

- 追踪现有布局/OCR → 表格与公式抽取 → 对象输出，定位父表遗漏或误分类的实际阶段。
- 复用现有对象裁剪恢复入口；已有 HTML 的 query_enhancement 分支继续禁止整页扫描。结构缺失恢复必须使用显式目标和来源，不能暗中扩大到相邻页。
- 明确父表、单元格、公式的关联，保留公式 LaTeX、编号、名称和语义的不同含义；不凭数组顺序或附近编号猜测身份。
- 为续表缺失上下文返回可定位的依赖信息，不自动抓取其他页。
- 保持已有正确表格/独立公式输出与渲染兼容，新增关系需提供消费者交接规则。

验收：合成的公式密集表、多面板页面、独立公式与续表用例；私有样本可用时检查 ASME p15/p23 的对应问题。离线原图检查只能证明样本基准，实际修复效果需授权真实模型后验证。

## G4：单元格图像与图像来源

目标：表内图像拥有真实资产来源和明确单元格关联，供 Membership 保存和显示。

工作：

- 查找现有 figure/crop/asset 输出与传输方法，复用同一路径，避免新增公共本地文件读取能力。
- 基于可靠布局坐标生成或返回图像引用与 parent table/cell 关系，注明 bbox 坐标系及页面身份；坐标不可靠则明确 unresolved，不猜测绑定。

- 原始 render_html 保持不变；如需派生渲染表示，显式独立输出，交由 Membership 接入。文字描述不能冒充原图。

验收：图像单元格、合并单元格、同页多表、多图、无可靠坐标、资源失败、重复调用；内容字节/尺寸/关联正确；无越界路径读取，无临时文件泄漏。端到端显示由 Membership 集成验收。
