# 平台架构：从客户视角和工具视角

> 版本：2025-01-11
> 角色：SaaS 平台架构设计
> 核心：两个独立的应用 vs 乙方工具体系

---

## 一、客户视角：两个独立的应用

### 1.1 客户部署形态

```
企业 A (新租户)
├─ Membership Admin UI (企业IT/HR部门用)
│  └─ 管理员维护组织结构、人员、权限、知识库
│
├─ WebApp (员工用)
│  └─ 员工查看待办任务、填表、审批、查看流程进度
│
└─ 共同后端: Membership + 知识库 + 流程引擎

企业 B (本地部署)
├─ 同样部署 Membership Admin UI
├─ 同样部署 WebApp
└─ 独立的数据库 + 知识库 + 流程引擎
   (与企业A完全隔离，不共享任何数据)

企业 C (SaaS 租户)
├─ 共享同一个 Membership 实例 (通过租户隔离 X-Tenant-ID)
├─ 共享同一个 WebApp 部署
└─ 在 Membership 中的数据完全隔离 (RLS)
```

## 二、乙方视角：三个独立的工具体系

### 2.1 工具体系的角色

```
乙方 (咨询/实施团队) 的工具箱:

┌─────────────────────────────────────────────────────────────┐
│ 工具层                                                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │

│ ├─ ProcessDesigner (BPMN-JS)                               │
│ ├─ FormDesigner (自定义表单编辑器)                         │
│ ├─ AIAssistantPanel (与 AICMDEngine 集成)                 │
│ └─ 用途: 设计单个流程 (快速原型、本地测试)                │
│                                                             │
│ 【工具2】AICMDEngine (AI 助手)                             │
│ ├─ 自然语言理解                                            │
│ ├─ BPMN-MCP (生成流程)                                     │
│ ├─ FORM-MCP (生成表单)                                     │
│ ├─ ProcessDesigner (编辑)                                  │
│ ├─ FormDesigner (编辑)                                     │
│ └─ 用途: 快速生成流程/表单 (提高效率 100倍)               │
│                                                             │
│ 【工具3】知识库管理工具 (待实现, 可能在 Membership Admin) │
│ ├─ 文档上传和管理                                          │
│ ├─ 版本控制                                                │
│ ├─ 应用范围配置                                            │
│ └─ 用途: 为企业导入政策文档                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘

乙方的工作流程:

1️⃣ 需求收集
   ├─ 与甲方沟通业务流程
   └─ 整理需求文档

2️⃣ 流程设计 (使用工具)
   ├─ 选项A: 用 BPM 编辑器手工设计 (快速原型)
   ├─ 选项B: 用 AICMDEngine AI 生成 (推荐, 快3倍)
   └─ 微调和优化

3️⃣ 知识库配置
   ├─ 收集甲方的政策文档 (采购政策、财务政策等)
   ├─ 上传到 Membership 知识库
   └─ 设置版本和应用范围

4️⃣ 部署上线
   ├─ 将流程/表单导出到 Membership
   ├─ 配置执行者 (角色/权限)
   ├─ 测试流程
   └─ 上线

5️⃣ 后期维护 (可选)
   ├─ 政策变化 → 更新知识库 (不改代码)
   ├─ 流程调整 → 在 Membership 中编辑
   └─ MCP 调用知识库进行决策

乙方可以给甲方的:
✅ 设计好的流程/表单 (JSON 文件)
✅ 政策文档 (PDF + 结构化元数据)
✅ 系统配置手册
✅ (可选) AICMDEngine/BPM 工具的访问权限 (如果甲方有团队维护)
```

## 四、不同客户场景

### 4.1 场景1：大型企业集团（新租户 SaaS）

```
企业: 500+ 员工的制造企业

部署形态: SaaS 租户
├─ Membership 共享实例 (通过 X-Tenant-ID 隔离)
├─ WebApp 共享实例
└─ 独立的知识库和流程定义

乙方工具的使用:
├─ AICMDEngine: 生成 5-10 个核心流程
├─ BPM: 用于原型和演示
├─ 知识库配置: 上传 30+ 个政策文档
└─ 培训: 3 天现场培训

交付周期: 2-3 个月

甲方得到:
├─ 5-10 个已配置的业务流程
├─ 30+ 个政策文档在知识库中
├─ 完整的权限体系
├─ 所有员工都能使用 WebApp 工作
└─ 永久使用权 (SaaS 订阅)
```

### 4.2 场景2：医药企业（本地部署）

```
企业: 药企，需要完全的数据隔离和审计

部署形态: 本地部署
├─ 独立的 Membership 实例 (Docker/K8s)
├─ 独立的 WebApp 部署
├─ 独立的知识库系统
└─ 全部数据存在企业内部

乙方工具的使用:
├─ AICMDEngine: 生成新药申报流程 (50+ 个节点)
├─ BPM: 用于流程设计和演示
├─ 知识库配置: 上传 100+ 个监管指南和政策
├─ 自定义 MCP: 开发 8 个专业领域 MCP
└─ 培训: 5 天现场培训 + 持续支持

交付周期: 4-6 个月

甲方得到:
├─ 完整的新药申报流程系统
├─ 100+ 个政策文档在知识库中
├─ 8 个自定义 MCP 支持智能决策
├─ 完整的审计日志 (符合监管要求)
├─ 全部代码和数据在企业内部
└─ 可独立运维和扩展
```

这是一个**三层架构的企业级平台**：

| 角度 | 用户看到 | 工具层 | 执行层 |
|------|---------|--------|--------|
