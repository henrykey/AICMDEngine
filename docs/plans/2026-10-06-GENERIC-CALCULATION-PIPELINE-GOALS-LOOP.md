# 通用计算书处理链路优化 — Goals Loop 执行计划

日期：2026-10-06
状态：MCP 源码、离线验证及服务部署完成；消费方联调／真实文档验收待完成。详见 [执行记录](2026-10-06-GENERIC-CALCULATION-PIPELINE-EXECUTION.md)。本文不代表总目标、部署或真实模型验收已完成。
目标仓库：AICMDEngine（Membership 的 AIPlanner 符号链接所指仓库）。

## 1. 总目标与成功定义

优化所有计算书共用的识别、预处理、语义结构化和校验链路，使自动上传、人工指定类型、整理已有内容、重新抽取及批量处理复用同一实现。不能针对某份标准、页码、表名或公式编写特例。

最终成功必须同时满足：

1. 从图片或已有内容得到可追溯、保真的转录；失败原因能定位到具体阶段。
2. 程序先分节、分项，模型负责理解每个单元，而不是重新猜测明确存在的边界。
3. 每个输入单元都有输出归属或显式未完成记录；不得静默丢项。
4. 公式保留 LaTeX 和语义说明，计算书保留整体语义说明；原文与生成解释分开。
5. 局部失败仍能提供有来源的可编辑草稿；新失败不覆盖旧草稿及已发布内容。
6. 单页审核/发布与跨页关联独立；本轮不实现跨页合并存储。
7. 普通数据表、既有批量接口、身份校验及请求预算不退化。

p13_t1 是复现样例之一，不是实现目标或唯一验收样例。测试必须包含非 ASME 的合成用例和不同版式。

## 5. 目标链路与契约原则

### 5.1 输入模式

- auto：自动入口沿用既有分类职责；确定计算书后进入共同链路。若已有可靠转录则复用，避免自动上传再做一次不必要的 OCR。若需要图片则真实发送图片。
- organize_existing：只读取明确指定的原始内容；程序预处理后做文本语义结构化，不发送图片、不静默转为 OCR。
- reextract：实际读取当前对象图片生成新转录，再进入共同链路；不得用旧文本冒充新转录。允许复用内容哈希和裁剪参数均匹配的页面渲染缓存，但必须区分渲染缓存与识别结果缓存。
- 人工类型为 calculation_sheet 时不允许自动分类覆盖；uncertain 不能在结果中被伪装成已完成计算书。

### 5.2 阶段 A：原始转录

模型任务以准确转录为主，保留标题、文字、公式、明显分隔；不同时要求复杂语义字段、唯一引用证明或跨页关联。优先使用现有图片调用机制。

转录输出采用最小明确契约；若模型输出结构化包裹，程序从经过验证的字段取得正文，不能依赖含糊地“找任意字符串”。空响应、无效 JSON、缺字段、截断、过滤、无效类型分别诊断。截断内容不当作完整成功。

保存原始转录与图像来源标识；物理页号、裁剪坐标、渲染选项、图像哈希和文档哈希分清，不能把 PDF 哈希误当图片或正文哈希。

### 5.3 阶段 B：确定性预处理

扩展既有 calculation_source_sections，不建立并行解析器：

- 纯文本/Markdown：识别明确标题与行边界，保护完整数学环境及多行公式。
- HTML：通过现有 HTML 解析能力读取块/单元格边界和文本；不得用单一正则剥标签导致粘连。colspan/rowspan 不是正文。
- 相邻独立公式可拆开；同一公式后的例外说明须保持关联；不能仅因逗号、等号或每个换行就切断公式。
- 不能证明是标题或独立项时，保留为未分类单元，不丢弃、不臆造左右列位置。
- 未闭合数学分隔符、嵌套结构、Unicode、CRLF、空行和脚注必须有测试。

模型输入示意（不是替换持久化 JSON 的新顶层数据库 schema）：

```json
{"source_revision":"content-hash","sections":[{"id":"s1","title":"Section title","items":[{"id":"s1-i1","text":"original unit text","source_range":[0,18]}]}]}
```

正式字段尽量使用当前 source_sections / source_item_id / source_range 契约。区间约定为半开区间，统一字符计数单位；Python Unicode 与 JS UTF-16 的差异必须测试。ID 在同一来源版本内稳定，不随前端重排改变；来源修改需生成新版本，不能沿用审核结论。

HTML 到规范文本的偏移不得冒充原 HTML 偏移。保留原始内容及可审计的转换关联，规范文本中的范围只指向该规范文本。

### 5.4 阶段 C：语义结构化

模型接收程序生成的 section/items 数组及稳定 ID，判断类型、填写当前计算书字段并生成语义说明。

- LaTeX、数值、单位、条件和引用是来源约束字段；语义说明是有来源依据的生成解释，不要求逐字出现在原文。
- 不以删除下标、改变不等号、去除例外条款等方式通过校验。
- 一项拆为多个输出时，均引用原单元 ID；确需多个输入共同解释时，必须有显式关联，不以隐式合并隐藏覆盖缺口。
- name/symbol 不适用时按现有契约表达，不用把整段 HTML 填进名称来满足非空条件。
- 复用现有语义生成能力；整份计算书及公式项的语义缺失须显式标注，不能只将 semantic_status 改为成功。
- 小输入可一次提交多个已分节单元；长输入按完整 section/item 批次处理，不切断公式，局部失败不丢弃已成功批次。

### 5.5 阶段 D：完整性校验与输出

以输入单元清单为依据，而不是模型自行声明“完整”：每个非空单元必须被结构化结果或保留原文的未完成项覆盖。标题、脚注和说明可属于节级字段，但去向明确。

拒绝未知/重复冲突 ID、跨文档引用和错误来源版本；相同公式在不同位置是不同来源，不能按文本相同去重。保留原文占位不等于成功结构化，分别报告 represented / structured / needs_review。

沿用现有 calculation_sheet_json 输出及现有 validator。任何扩展必须在共享 producer/consumer fixture 中明确，并验证 Membership 消费能力；不要无协商替换当前契约或让新字段只停留在 MCP 输出。

## 6. 恢复、诊断与预算

每阶段报告状态、具体错误码、输入/输出单元计数、内容版本及实际模型/引擎信息。诊断错误码以现有命名规则扩展，需区分 transcription_missing、response_invalid、response_truncated、framing_failed、semantic_partial 等类别；具体名称在契约冻结时确定。

转录成功而结构化失败时返回可恢复转录，Membership 负责持久化；下一次显式重试允许从该转录继续。MCP 不直接写 Membership MongoDB，不引入隐式全局缓存。持久化及恢复入口未联调前只能标记 MCP 能力完成，不能宣称端到端恢复完成。

有界重试：按阶段预先分配总调用预算与超时；统计所有实际 HTTP 请求，包括 SDK/transport 重试。拆阶段不能绕过已有 physical_request_limit。预算不足返回明确 partial/failed，不无限重扫。

默认先修复/重试失败阶段；重新抽取必须由对应操作触发。失败不自动发布，不替换人工编辑或已发布版本。

日志只记录必要身份、阶段、哈希、尺寸、计数及错误类别，不记录凭据、完整文档、prompt 或模型正文。诊断原件需要时作为受控临时产物，不提交真实文档、响应或秘密到 Git；合成 fixture 可提交。

## 7. Goals Loop 执行顺序

每轮流程：收集证据 → 写失败测试 → 最小实现 → codegraph sync → 定向测试 → 检查差异 → 更新执行记录。失败时修正本轮，不跳过验收进入下一轮。不用扩大重试预算掩盖结构缺陷。

| Loop | 目标与工作 | 必须提供的验收证据 |
|---|---|---|
| G0 基线与复现 | 核对真实入口、运行版本、crop、模型参数、失败输出结构；与 WebUI 比较输入条件 | 调用链、基线摘要、已证实/未证实清单；不凭截图断言根因 |
| G1 冻结契约与失败测试 | 定义阶段边界、source 单元、结果覆盖、预算和可恢复产物；复用旧契约 | mock 再现 source_text 异常、HTML 粘连、漏项；新测试修改前因目标原因失败 |
| G2 转录与预处理 | 分离图片转录；扩展已有预处理覆盖 HTML/文本/数学环境 | 多版式 fixture；源内容可追溯；无 HTML 标签泄漏；未知结构保留 |
| G3 结构化与对齐 | 输入数组、稳定 ID、独立语义说明、局部失败占位 | 缺项/重复/未知 ID/错误版本负例；不改变公式；完整覆盖但不伪装成功 |
| G4 统一入口与恢复 | 自动上传、人工类型、organize_existing、reextract、batch 复用；阶段预算与恢复契约 | 真实请求构造测试；organize 无图片；reextract 有当前图片；批量独立对象失败隔离 |
| G5 消费方联调 | 提交 Membership 所需变更清单和 fixture；与消费方确认持久化、状态与编辑兼容 | producer/consumer fixture 一致；人工修改保留；新旧草稿区分；失败阶段可重试 |
| G6 真实验收与交付 | 在授权环境验证真实模型、服务镜像和人工平台 | 逐项对照、发布刷新回读、普通数据表回归、剩余限制；源码与部署证据分列 |

每轮记录：完成/未完成、变更文件、测试命令及结果、发现、下一步、阻塞依赖。不得把全部 TODO 标成完成而只交离线测试。

## 8. 必测矩阵

- 公式为主：同一行多公式、多行公式、上下标、分式、分段条件。
- 符号说明为主：多个符号共用说明，混合语言；符号列表不是被强制套成等式。
- 混合：输入、公式、校核不等式、例外说明、脚注和外部引用。
- HTML：多行/合并单元格、实体转义、公式嵌入、无换行 HTML。
- 文本：CRLF、空行、标题没有后接公式、Unicode 非 BMP、未闭合数学块。
- 重复来源：同公式多次出现，不去重，不错误清除其他项的审核问题。
- 模型异常：空值、错误类型、JSON 无效、字段缺失、截断、超时、局部遗漏、未知 ID。
- 操作模式：auto、manual hint、organize_existing、reextract、单个/批量、预算 0/不足/耗尽。
- 安全/隔离：不同文档同名表、错误页/对象 ID、跨租户来源、旧版本恢复、来源中的提示注入文本。
- 回归：普通 data_table 提取及查询契约不变；已有计算书编辑/审核/发布 JSON 仍可读写。

真实样例包含但不限于 p13_t1：该图预期 4 条校核及 9 条符号说明，需以原图核对；p12 的 Equation Constants、其他标准及至少一份不同语言/版式样例也应参与。固定数量只能写入对应 fixture 的断言，不能写入生产分支。
