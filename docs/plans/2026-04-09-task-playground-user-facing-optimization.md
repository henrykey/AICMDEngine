# Task Playground 用户态对话优化方案

日期：2026-04-09

## 背景

当前 Task Playground 默认同时展示聊天区和 Planner & Executor 调试面板。对于正式用户，这会暴露大量内部技术信息，包括：

- HTTP 命令和路径模板
- MCP/tool 名称
- Step 级状态
- 原始错误栈
- 检索诊断信息

这类信息适合测试和开发，不适合作为正式对话体验。用户真正需要的是：

- AI 对需求的自然语言理解
- 业务过程的自然语言反馈
- 最终结果或明确的下一步建议

## 目标

将 Task Playground 调整为“用户态对话优先，调试信息折叠”的双层结构：

1. 默认界面只展示自然语言说明、执行进度摘要和最终结果。
2. 规划、检索、步骤、原始错误保留在调试视图中，供测试和开发使用。
3. 对“先查列表，再定位实体 ID，再执行下一步”的任务，默认只展示业务结论，不展示中间列表噪音。

## 设计原则

### 1. 用户态与调试态分层

- 用户态：自然语言理解、状态反馈、结果结论
- 调试态：计划步骤、命令明细、参数、原始响应、错误堆栈

### 2. 用户态消息由后端生成

前端不再从技术步骤中猜测用户可读文案。后端统一返回：

- `assistantMessage`
- `userPlan`
- `userSummary`

这样可以保证对话区、右侧摘要区和后续自动化场景使用同一套话术。

### 3. 中间检索默认隐藏

像 `GET /v2/members` 这样的查找型步骤，默认不展示前五条结果或 `... and more`。正式界面只展示：

- 已找到目标成员
- 未找到目标成员
- 找到多个候选项

## 数据协议调整

### 1. 任务规划响应

`TaskPlanResponse` 增加：

- `assistantMessage`: 给聊天区直接展示的自然语言回复
- `userPlan`: 用户态计划摘要
- `debugAvailable`: 是否存在可展开调试细节

`userPlan` 结构：

- `headline`: 摘要标题
- `summary`: 自然语言说明
- `steps`: 面向用户的简化步骤
- `nextAction`: 下一步说明
- `debugHint`: 调试提示

### 2. 执行详情响应

`ExecutionDetailResponse` 增加：

- `userSummary`: 面向用户的执行摘要

`userSummary` 结构：

- `headline`
- `summary`
- `statusLabel`
- `nextAction`
- `detailLines`
- `debugHint`

## 前端展示策略

### 1. Chat 面板

聊天区默认展示：

- 用户输入
- `assistantMessage`

不再要求用户从右侧步骤卡片理解系统打算做什么。

### 2. Planner & Executor 面板

默认展示：

- 用户态任务摘要卡片
- 执行状态摘要卡片
- 执行按钮

折叠展示：

- 检索诊断
- Step 列表
- 原始错误信息
- 命令和参数

### 3. 调试开关

在面板中提供“调试详情”折叠区，测试与开发可展开查看全部技术细节。

## 后端逻辑策略

### 1. 规划阶段

规划成功后由后端生成用户态计划摘要，例如：

- 我会先查找名为“朱国栋”的成员，然后查询其访问权限。
- 执行时默认只展示对你有用的过程和结果，内部步骤会放在调试详情里。

### 2. 直接执行阶段

对于 Direct MCP 这类一步完成的任务，也返回自然语言摘要，而不是只回传 tool 信息。

### 3. 执行阶段

执行详情接口返回统一的 `userSummary`：

- 执行中：系统正在按规划执行这次请求
- 已完成：系统已经完成这次请求
- 未完成：系统没有完整完成这次请求

技术错误在用户态统一转译为更易理解的话术，原始错误保留在调试详情。

## 查找型任务专项要求

对于“查某个成员/组织/角色的信息”这类任务：

1. 中间列表查询只作为内部检索步骤。
2. 若未命中目标实体，应直接返回用户态结论：
   - 未找到成员“朱国栋”。请确认名称是否正确，或先创建该成员。
3. 若命中多个实体，应返回歧义提示。
4. 只有在唯一命中时才继续后续依赖 `id` 的步骤。

本次实现先完成用户态摘要和调试折叠；更细的 lookup 分支控制可继续沿此方案增强。

## 实施内容

### 后端

- 扩展 `TaskPlanResponse`
- 扩展 `ExecutionDetailResponse`
- 在 `PlanningEngine` 中生成 `assistantMessage` 和 `userPlan`
- 在 `DirectMCPExecutor` 中生成直接执行的用户态摘要
- 在 `ExecutionEngine.get_execution()` 中生成 `userSummary`

### 前端

- Chat 面板优先展示 `assistantMessage`
- Planner & Executor 默认展示用户态摘要
- 调试细节折叠展示
- 保留步骤、检索、错误等调试信息，默认隐藏

## 验收标准

1. 用户在聊天区提交任务后，能直接看到自然语言计划说明。
2. 右侧面板默认不展示 HTTP 命令、路径模板和原始错误。
3. 调试人员仍可展开看到完整步骤、命令和错误细节。
4. Direct MCP 与 CmdEngine 规划路径都能返回用户态摘要。
5. 执行失败时，用户默认看到的是自然语言失败说明，而不是技术栈。

## 后续增强

1. 为 `lookup step` 增加标准语义和短路执行能力。
2. 增加“用户模式 / 测试模式 / 开发模式”显式切换。
3. 将技术错误统一映射到业务错误模板。
4. 将最终结果摘要也统一为后端生成，减少前端格式分支。
